# DeepSeek Work 设计文档

本文档描述 DeepSeek Work 的架构、模块职责、核心流程与关键技术决策。面向想阅读/二次开发源码的人；用户视角的使用说明见根目录 [README](../README.md)。

## 1. 定位与技术选型

**定位**：单文件 Windows 桌面工具。把「本地 gguf 模型 bat 启动 + DeepSeek Harness web 界面」的重复操作收敛为一次点选，并顺带展示电脑硬件信息。

| 选型 | 决定 | 理由 |
|------|------|------|
| 桌面框架 | Wails v2.15.0 | Go 后端 + WebView2 前端，单 exe 交付，无 Node 运行时 |
| 前端 | 原生 HTML/CSS/JS（`go:embed` 内嵌） | 无构建步骤（`frontend:build` 为空），wails build 一步出 exe |
| 编译 | 无 CGO | 交叉编译/分发简单，`wails build` 直接产出 `DeepSeek Work.exe` |
| 系统信息 | WMI（yusufpapurcu/wmi）+ nvidia-smi + gopsutil | 免管理员权限、逐行容错，兼容各种 Windows 机器 |
| 配置 | `%APPDATA%\DeepSeek Work\config.json` | 与 exe 位置无关，重装/移动 exe 不丢配置 |

## 2. 架构总览

```
┌────────────────────────────────────────────────────────┐
│ frontend/（WebView2 渲染，go:embed 进 exe）             │
│  index.html ─ app.js ─ styles.css                      │
│      │  window.go.main.App.*（wailsjs 自动绑定）        │
│      │  runtime.EventsOn("status", …)  ← 事件推送      │
├──────┼─────────────────────────────────────────────────┤
│ main.go    窗口选项（Frameless/透明背景/WebView2 数据目录）│
│ app.go     App 结构体：绑定方法 + 状态机（waiting 原子位）  │
│ config.go  Config 读写/默认值/迁移                       │
│ presets.go 预设列表构造（纯函数）                        │
│ sysinfo.go 硬件采集（纯函数，逐行降级）                   │
│ launcher.go 端口探测 / CreateProcessW / taskkill / 浏览器  │
└────────────────────────────────────────────────────────┘
        │ 子进程
   ┌────┴─────────────────────────────┐
   │ 新控制台窗口: cmd /c <bat>        │  隐藏窗口: cmd /c <harnessCmd>
   │ （llama-server, :8080）          │  （DeepSeek Harness, :3080）
   └──────────────────────────────────┘
```

数据流只有一个方向：**前端 → 绑定方法（app.go）→ launcher.go 副作用**；状态变化经 `runtime.EventsEmit("status", …)` 回推前端。Go 侧唯一共享可变状态是 `App.waiting`（atomic.Bool，表示正在等待 8080 就绪）与 `Launcher.mu` 保护的 `modelProc`。

## 3. 模块职责

### main.go — 进程入口
- `//go:embed frontend` 把前端资产打进 exe。
- 窗口：`Frameless + BackgroundColour(0,0,0,0)`（透明底，毛玻璃由 CSS `backdrop-filter` 实现）；460×760，最小 400×640。
- `WebviewUserDataPath = %APPDATA%\DeepSeek Work`：WebView2 浏览器数据与 config 同目录，避免在 `%APPDATA%` 下多出一个与 exe 同名的杂散目录。

### app.go — 绑定与流程编排
| 方法 | 作用 |
|------|------|
| `GetSysInfo` | 一次性采集电脑信息（前端启动时调一次） |
| `ListPresets` | 当前预设（ExtraBats 去重排序） |
| `AddBat` / `RemoveBat` | 预设增删（持久化；`pkg/dialogs` 在 wails v2.15 已移除，用 `runtime.OpenFileDialog`） |
| `StartModel` | 完整流程：启动 bat → 后台 goroutine 每 1s 轮询 8080（上限 180s）→ 就绪后 `EnsureHarness` |
| `StartBatOnly` | 只启动 bat，不轮询、不启 harness |
| `SkipWait` | 清掉 `waiting` 并立即 `EnsureHarness` |
| `EnsureHarness` | 3080 已监听→复用；否则 `StartHarness` 后 `WaitPort`（30s） |
| `OpenHarnessBrowser` | `chrome.exe --new-window http://127.0.0.1:<harnessPort>`，Chrome 缺失回退 `rundll32` |
| `SetHarnessCmd` / `GetConfig` | 自定义命令持久化 / 读配置 |
| `StopModel` | `taskkill /T /F` 整棵模型进程树 |
| `QuitApp` | 可附带停模型后 `runtime.Quit` |

`StartModel` 的返回值是阶段串（`"running" | "port-busy" | "already" | "error"`），前端据此决定弹不弹「8080 已占用」确认框——避免为一次性交互起复杂事件协议。

### config.go — 配置
- `LoadConfig`：在 `defaultConfig()` 上直接 `json.Unmarshal` —— 缺字段保留默认；整体非法 JSON 则回退全新默认（配置损坏自愈）。
- 路径全部运行时 `os.Getenv("APPDATA")` 拼接，代码里不写死任何用户目录。
- `migrateLegacyConfig`：一次性把旧位置 `%APPDATA%\ai-starter\config.json` 复制到新位置（不覆盖、不删旧文件）。

### presets.go — 预设
纯函数、无状态：`ListPresets(cfg)` 对 `ExtraBats` 做 `filepath.Abs` 去重、按 (Name, Path) 排序；`ParsePresetName` 从文件名剥掉 `.bat` 与开头序号/分隔符得到展示名，从 bat 内容里找 `MODEL_PATH=` 取模型文件名作副标题。文件缺失的条目**保留**（`Exists=false`），由 UI 置灰标「文件缺失」而不是静默丢弃。

### sysinfo.go — 电脑信息
行式模型 `SysInfo{Rows []InfoRow}`，`InfoRow` 可带 `Subs` 子行（多显卡/多硬盘/多显示器场景）。**每行独立采集、独立降级**：任何一项失败只影响自己，值置「—」。

| 行 | 数据源 | 降级策略 |
|----|--------|----------|
| 处理器 | WMI `Win32_Processor` | 剥掉「N-Core Processor」尾巴，中文核数（`cnNum`）补位 |
| 主板 | WMI `Win32_BaseBoard` | 厂商走 `vendorMap` 中文映射（长前缀在前），未知厂商回显原名 |
| 内存 | gopsutil `mem.VirtualMemory` + WMI `Win32_PhysicalMemory` | 容量必显示；插槽构成/代际/频率取不到就省略 |
| 显卡 | WMI `Win32_VideoController` + `nvidia-smi` | NVIDIA 卡用 nvidia-smi 的显存（WMI `AdapterRAM` 常不准），按归一化卡名配对；WMI 全挂时退回 nvidia-smi 列表；集显在前 |
| 显示器 | WMI `Win32_PnPEntity(PnpClass='Monitor')` + `Win32_DesktopMonitor` | 尺寸能配对到才显示；Generic Monitor 只留括号内串 |
| 磁盘 | WMI `Win32_DiskDrive` + `Win32_LogicalDiskToPartition` | C 盘所在物理盘（Antecedent/Dependent 关系解析）标「主硬盘」置顶；容量用十进制 GB 与市售标称一致 |
| 系统 | gopsutil `host.Info` | 单串拼接 |

### launcher.go — 进程与端口
- `PortOpen` / `WaitPort`：`net.DialTimeout` 探测 127.0.0.1，500ms 间隔轮询。
- `StartModel`：**直接 `CreateProcessW` P/Invoke**，见下节关键决策 #1。
- `StartHarness`：`cmd.exe /c <完整命令行>` + `CREATE_NO_WINDOW`；启动前校验命令第一个 token 若是文件路径则先 `os.Stat`（把「文件不存在」从 30s 超时提前为即时报错）。
- `StopModel`：`taskkill /T /F /PID`（整棵树，含 bat→llama-server 子进程）。
- `OpenBrowser`：Chrome `--new-window` 优先，`rundll32` 回退。

## 4. 核心流程

### 一键启动（StartModel）

```
前端点「一键启动」
  → SetHarnessCmd(输入框当前值)     # 非空才持久化
  → StartModel(path)
      → waiting 已置？→ "already"
      → 8080 已监听？→ "port-busy"（前端弹窗确认是否只开 harness）
      → CreateProcessW 新控制台跑 bat   # llama-server 日志可见
      → waiting=true, emit(starting)
      → goroutine: 每 1s 探测 8080 × 180 次
           就绪 → waiting=false → EnsureHarness()
                 ├─ 3080 已监听 → 直接复用
                 └─ 否则 StartHarness(harnessCmd) → WaitPort(30s)
                 → emit(ready) → 前端 OpenHarnessBrowser()
           超时 → emit(timeout, 提示看控制台窗口)
```

「单独启动 bat」只走 `CreateProcessW` 那一步，之后 `emit("bat-only", …)`，用户需要时再手动点「启动 DeepSeek Harness」。

### 状态机

`App.waiting`（atomic.Bool）是唯一的并发开关：
- 置位：`StartModel` 成功启动 bat 后。
- 清除：就绪 / 超时 / `SkipWait` / `StopModel`。
- 期间再点启动 → `"already"` 幂等返回；UI 侧两启动按钮在 `busy` 期间禁用。

## 5. 关键技术决策与坑

1. **bat 必须用 CreateProcessW，不能用 os/exec**（v1.0.15 修复的根因）：Go 1.27 的 `os/exec` 对子进程无条件设置 `STARTF_USESTDHANDLES` 并把未显式指定的 std 流指向 NUL 句柄。于是即使 `CREATE_NEW_CONSOLE` 开了可见控制台窗口，bat 的 stdout/stderr 仍被接到 NUL —— 窗口开了、llama-server 也起来了，但日志全部静默丢弃。解决：直接 P/Invoke `CreateProcessW`，`STARTUPINFO.dwFlags=0`（不设 `STARTF_USESTDHANDLES`），系统自动把新控制台的 std 句柄赋给子进程，与用户手动双击 .bat 的语义完全一致。
2. **LazyProc.Call 的错误判断**：Go 1.27 的 `syscall.NewLazyDLL(...).NewProc(...).Call` 无条件返回 `GetLastError()`（成功时是 `Errno(0)` 而非 nil），必须按 errno **数值**判断成败，不能判 `err != nil`。
3. **.cmd 文件不能直接 CreateProcess**：报 `ERROR_BAD_EXE_FORMAT`，所以 harness 命令一律 `cmd.exe /c <cmdline>` 执行，配合 `CREATE_NO_WINDOW` 隐藏。
4. **端口复用优先**：harness 端口 3080 只要有人在监听就复用（`EnsureHarness` 第一行），本工具永不重复启动第二个实例；模型端口 8080 被占用则交还用户决策（弹窗）。
5. **窗口拖动不用手写 JS 位移**：CSS 里 `--wails-draggable: drag` 命中 wails 内置机制，wails 的 runtime JS 在 mousedown 后于 UI 线程 `PostMessage(WM_NCLBUTTONDOWN, HTCAPTION)`，由 **Windows 系统移动循环**接管窗口移动 —— 与资源管理器窗口同一套机制，手感一致且不吃 CPU；四边 6px 原生缩放由 Frameless 自动启用。注意 CSS 自定义属性会继承，按钮区域必须显式 `--wails-draggable: none` 覆盖，否则点按钮也会拖窗口。
6. **WMI 全量容错**：精简系统镜像常缺 WMI 类/字段，所有查询都包在「失败即降级」的分支里；NVIDIA 显存不信 WMI（`AdapterRAM` 常是假值），用 `nvidia-smi` 并按归一化卡名（去空格/去 nvidia 前缀/小写）配对。
7. **控制台窗口不闪**：GUI 进程调 `nvidia-smi` 必须 `CREATE_NO_WINDOW`（0x08000000），否则每 3s 弹黑窗。
8. **配置自愈**：`LoadConfig` 在默认值上 unmarshal，坏 JSON 整体回退默认 —— config.json 删掉或改坏都不影响启动。
9. **harness 不跟踪进程句柄**：harness 由 `cmd /c` 启动后自行托管（端口复用优先意味着它也可能根本不是本工具启动的），所以只探测端口就绪，不保存/不杀其进程；`taskkill` 只用于本工具自己启动的模型进程树。

## 7. 构建与分发

- `wails build`：重新生成 `frontend\wailsjs` 绑定 → 编译 → `build\bin\DeepSeek Work.exe`。无前端构建步骤（原生 JS，无 npm）。
- 图标：`build\appicon.png`（窗口图标）+ `build\windows\icon.ico`（exe 图标，PNG 编码的多尺寸 ico），源文件 `build\dsh-icon-black.svg`。
- 首次分发注意：未签名 exe 会触发 SmartScreen/杀软提示，属预期。
